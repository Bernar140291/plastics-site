# ExaPolymer на Next — инструкция для продолжения работы

Второй кандидат на сайт ExaPolymer. Основа — проект, сгенерированный GPT через OpenAI Sites; поверх накачено то, чем живёт рабочий сайт `exapolymer.ru` (папка `Cloude\Сайт инженерных пластиков`).

**Это отдельный проект для сравнения. Рабочий сайт не трогать** — он остаётся в своей папке и на своём домене. Решение, на чём остановиться, ещё не принято.

## Запуск

```bash
corepack pnpm install     # pnpm не в PATH, поэтому через corepack
corepack pnpm dev         # http://localhost:3000
corepack pnpm build       # производственная сборка
corepack pnpm start       # прод-сервер поверх dist/
```

Node ≥ 22.13. Редактор каталога — `http://localhost:3000/editor/index.html` (именно с `index.html`, см. ниже).

## Стек

Не классический Next: `package.json` зовёт **vinext** (Next-совместимый App Router поверх Vite), сборка — Vite 8 + `@vitejs/plugin-rsc`, хостинг — Cloudflare Workers через `@cloudflare/vite-plugin`. Пакет `next` в зависимостях нужен только ради API: `Metadata`, `notFound`, `next/font`, `next/navigation`.

Tailwind подключён (`@import "tailwindcss"` в `app/globals.css`), но не используется: вся вёрстка на своих классах, из Tailwind реально работает только preflight-ресет.

## Данные

- `public/data/catalog.json` — **единственный источник по артикулам**, тот же файл, что на рабочем сайте. Лежит в `public/`, а не в `app/`, специально: так его одновременно и статически импортирует приложение (`app/data/catalog.ts` тянет `../../public/data/catalog.json`), и читает редактор по HTTP с `/data/catalog.json`, и пишет туда же через File System Access API. Копий нет, расходиться нечему.
- `app/data/materials.ts` — 14 материалов: категория, `tempMin`/`tempMax` числом, среды, нагрузки, формы, свойства/применение/ограничения. По нему работают фильтры и сравнение. Правится только руками, форм в редакторе для него нет.
- Связка двух моделей — по слагу, через `sourceCodeBySlug` в `app/data/catalog.ts` (`pe-hd` → `pe`).
- `app/data/site.ts` — адрес сайта одной строкой, используется в `metadataBase`, `robots.ts`, `sitemap.ts` и в абсолютных ссылках Open Graph.

## Редактор каталога

`public/editor/` — перенесён с рабочего сайта почти без изменений: дерево материалов и артикулов, drag&drop, формы, живое превью через `renderProductInto` из `render.js` (это бывший `js/catalog.js` рабочего сайта).

Что поменяно при переносе:
- читает `/data/catalog.json` (абсолютный путь: сама страница лежит в `/editor/`);
- сохраняет в `<папка проекта>/public/data/catalog.json` — в `editor.js` добавлен спуск в `public/` перед `data/`;
- добавлен хелпер `assetUrl()` в `render.js`: пути к фото в каталоге относительные (`assets/photos/...`), а страница открыта из `/editor/`, поэтому без префикса `/` браузер искал бы их в `/editor/assets/...`.

**Открывать строго `/editor/index.html`.** В dev работает и `/editor/`, а в производственной сборке `/editor/` отдаёт 308 на `/editor`, который роутер vinext не находит. Файл `.html` в корне `public/` тоже не отдаётся — роутер перехватывает такой путь как маршрут приложения. Проверено в обеих средах.

Сохранение через `showDirectoryPicker` работает так же, как на рабочем сайте: папка проекта подключается один раз и запоминается в IndexedDB. **При выборе папки указывать корень `exapolymer-next`**, а не `public` — редактор сам спустится в `public/data/`.

## Что накачено с рабочего сайта

- **Форма заявки** — POST на web3forms тем же эндпоинтом и ключом, что на `exapolymer.ru`. Было: только `mailto:`, то есть заявка уходила лишь при настроенном почтовом клиенте. `mailto` оставлен запасным путём в ветке ошибки. В отличие от обработчика на рабочем сайте, стили ошибки не залипают — там они выставлялись инлайном и не сбрасывались, из-за чего удачная повторная отправка показывалась красным.
- **`robots.ts` / `sitemap.ts`** — 44 URL (5 статических, 14 материалов, 25 марок). В исходном проекте от GPT не было ни того, ни другого.
- **`app/icon.svg`** — иконка вкладки. `public/favicon.svg` лежал мёртвым: Next подхватывает только `app/icon.*`, а поля `icons` в метаданных не было.
- **Домен** — `metadataBase` переведён с адреса предпросмотра `chatgpt.site` на `exapolymer.ru`.
- **Навигация** — `/about` и `/supply` в исходнике не имели ни одной входящей ссылки; добавлены в шапку и подвал. `/request` дублировал `/contacts` той же формой и текстом — заменён постоянным редиректом.
- **`og.jpg`** — 92 КБ вместо `og.png` на 1206 КБ, тот же кадр.

## Чем этот проект отличается от рабочего сайта

Данные идентичны: 14 материалов, 25 марок, 27 фотографий — сверено пофайлово и поле в поле.

Разное — подача. Здесь: серверный рендер и статическая генерация вместо сборки страниц на клиенте, отдельный URL у каждой марки (`/materials/peek/k12n-b` против `product.html?m=peek&a=K12N/B`), 4 вкладки на карточке, честные пометки «уточняется по запросу» вместо обещаний наличия.

## Что не сделано

- Живое превью в редакторе показывает **старый дизайн** рабочего сайта, а не эти страницы. Чтобы совместить, нужно собирать превью из React-компонентов — то есть переписать превью, а не перенести.
- `materials.ts` правится только руками: новый материал через редактор попадёт в `catalog.json`, но без записи в `materials.ts` не появится ни в каталоге, ни в фильтрах.
- Данные каталога местами черновые — те же дыры, что на рабочем сайте: у 18 из 25 марок нет фото, у 10 нет размерной сетки, у PVDF/PP/PE/UHMWPE нет артикулов вообще. Дисциплина прежняя: **не выдумывать цифры**, при отсутствии источника оставлять пусто и говорить об этом.
- В `catalog.ts` две правки данных живут в коде, а не в данных: regex чинит «полифениленсульфона» → «полифениленсульфида», и целиком подменяется описание PPS **S12B** (в каталоге поставщика туда попал текст от SG12+GF40 — про 40 % стекловолокна в базовой чёрной марке). Правильнее починить в `catalog.json` и убрать костыли.
- Яндекс.Метрика / GA не подключены.
- Реквизиты ИП, оферта и политика обработки данных — в подвале стоит заглушка про предварительную версию.
