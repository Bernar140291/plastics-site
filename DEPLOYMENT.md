# ExaPolymer: подготовка и публикация

## Текущий результат

В этой папке находится новая версия сайта на Vinext/Vite/React. Старый рабочий сайт — отдельная статическая версия, связанная с `https://github.com/Bernar140291/plastics-site` и Cloudflare Workers. В `exapolymer-next` remote пока не настроен. Изменения этого этапа не отправлялись в GitHub, домен не переключался.

Каталог: 10 материалов, 29 марок. Главное изображение и галерея есть у каждой марки. Для 9 ранее пустых марок добавлены существующие ИИ-иллюстрации заготовок и применения. Они помечены в данных и интерфейсе. Происхождение файлов — `IMAGERY.md`.

## Локальная проверка

Проверено 18 сентября 2026 года:

- lint, TypeScript и проверка каталога — без ошибок;
- production-сборка — успешно;
- локальный Cloudflare Worker из `dist/server/wrangler.json` — успешно: 45 страниц, 93 адреса изображений, 6 ожидаемых 404, перенаправление `/request`, robots и sitemap;
- `wrangler deploy --dry-run` — успешно; публикация при этом не выполнялась;
- в браузере проверены мобильная карточка ABS B6N, иллюстрация применения, вкладки, увеличение изображения и подготовка тестовой заявки без отправки. Результат подготовки получает фокус и виден на мобильном экране;
- синтаксис скриптов локального редактора — без ошибок.

Доставка реального письма и публичный адрес новой версии не проверены. Автоматическая отправка и индексация остаются выключенными.

Node.js 22.13+; зависимости фиксирует `pnpm-lock.yaml`. Не обновлять пакеты перед первым размещением без отдельной проверки.

```sh
corepack pnpm install --frozen-lockfile
corepack pnpm lint
corepack pnpm typecheck
corepack pnpm check:catalog
corepack pnpm build
node node_modules/vinext/dist/cli.js start --hostname 127.0.0.1 --port 3100
```

Во втором терминале:

```sh
node tools/smoke.mjs http://127.0.0.1:3100
```

Для проверки именно среды Cloudflare, вместо Node-сервера:

```sh
node node_modules/wrangler/bin/wrangler.js dev --local --ip 127.0.0.1 --port 3101 --config dist/server/wrangler.json
node tools/smoke.mjs http://127.0.0.1:3101
```

Вторую команду запускают в отдельном терминале, пока локальный Worker работает. Проверка упаковки без публикации: `node node_modules/wrangler/bin/wrangler.js deploy --dry-run --config dist/server/wrangler.json`.

Smoke-проверка ожидает адрес `https://exapolymer.ru` и режим noindex по умолчанию. Для иной сборки задайте `EXPECTED_SITE_ORIGIN` и при необходимости `EXPECTED_INDEXABLE=true`. Проверяются все страницы и изображения каталога, canonical, robots, sitemap, 404, перенаправление `/request` и недоступность редактора в production. Это не проверка доставки писем.

Редактирование каталога: `corepack pnpm dev`, затем `/editor/index.html`. Подключать корень **exapolymer-next**. Редактор не входит в production-сборку. JSON записывать через `node tools/write-catalog.mjs <файл>`, чтобы избежать чтения полузаписанного файла.

## Параметры сборки

### Дополнительная проверка интерфейса — 21 сентября 2026

По чек-листу Impeccable проверены 9 типов страниц при ширине 390, 768 и 1440 px (27 сочетаний); горизонтального переполнения страницы не обнаружено. Исправлены закрытие меню по Escape и при переходе к широкому экрану, перенос клавиатурного фокуса к сравнению, подписи выбора материалов, обработка пробелов в поиске, очистка артикула при смене материала и скрытие устаревшего подготовленного письма после изменения формы. Эти взаимодействия проверены в браузере без отправки письма.

Увеличен текст карточек, таблиц, ссылок и мобильных полей; улучшены индикаторы фокуса. В физических параметрах значение перенесено рядом с названием показателя; таблицы доступны для прокрутки с клавиатуры. Анимация появления отключена при запросе уменьшенного движения.

Проверка выполнена в браузере Codex с имитацией ширины экрана, не на физических устройствах. Safari/iOS и реальная доставка почты не подтверждены. Автоматический движок Impeccable недоступен; использованы ручная проверка и Lighthouse. Молочная версия изображения подключена к главной и социальному превью.

### Исправления после финального аудита — 22 сентября 2026

Исправлены два нарушения доступности: контраст номеров этапов и подписи в блоке запроса, а также доступное имя логотипа. Lighthouse после исправлений: mobile Performance 98, Accessibility 100, Best Practices 100, LCP 2,1 с; desktop Performance 100, Accessibility 100, Best Practices 100, LCP 0,5 с. SEO остаётся 69 только из-за намеренного `noindex` предварительной сборки.

Главное изображение переведено в WebP: 25 КБ для экранов высокой плотности и 12 КБ для обычного компьютерного экрана вместо JPEG 160 КБ. Социальное превью заменено на утверждённую молочную версию. Для HTML-ответов добавлены CSP, `Referrer-Policy`, `X-Content-Type-Options`, `X-Frame-Options` и `Permissions-Policy`. `.wrangler/**` исключён из lint; исходный код проверяется без предупреждений.

Скопируйте `.env.example` в `.env.local` для локальной работы либо задайте переменные в настройках сборки Cloudflare. Значения встраиваются при сборке: после изменения нужно пересобрать сайт.

- `SITE_ORIGIN`: полный адрес новой публикации без пути, например `https://exapolymer-next.<account>.workers.dev`. Для переключения домена — `https://exapolymer.ru`.
- `SITE_INDEXABLE=false`: режим предварительной версии; robots.txt запрещает обход, метаданные содержат noindex. Это не защита доступа: по прямой ссылке сайт доступен.
- `FORM_DELIVERY_ENABLED=false`: форма только формирует текст в памяти вкладки, затем посетитель открывает письмо или копирует текст. Она не отправляет поля в Web3Forms. Кнопка честно подписана «Подготовить заявку».
- `PRIVACY_OPERATOR`: полное ФИО оператора либо наименование организации/ИП.
- `PRIVACY_OPERATOR_ADDRESS`: адрес оператора для обращений. Банковские реквизиты, ИНН и платёжные данные этой настройке не нужны.

При пустых сведениях оператора `/privacy` и `/consent` показаны как проекты документов. Для `SITE_INDEXABLE=true` или `FORM_DELIVERY_ENABLED=true` сборка требует заполнить имя и адрес. Это техническая проверка заполнения, не юридическое подтверждение соответствия.

## GitHub → Cloudflare Workers

Новая версия требует серверного Worker. Загрузка только `public/` или прежняя настройка публикации статических HTML не подходят.

1. Сохранить старую версию и её рабочую конфигурацию. Подготовить отдельный репозиторий или ветку для этой папки; существующий репозиторий не перезаписывать без решения владельца.
2. В Cloudflare создать отдельный Worker для предварительной проверки новой версии, подключив выбранный GitHub-репозиторий/ветку. Рабочее имя в конфигурации новой версии — `exapolymer-next`.
3. Root directory — папка, содержащая `package.json` и `vite.config.ts`. Node.js — 22. Команда сборки: `corepack pnpm build`. Команда публикации: `node node_modules/wrangler/bin/wrangler.js deploy --config dist/server/wrangler.json`.
4. В окружении сборки указать фактический `SITE_ORIGIN`; на предварительном адресе оставить `SITE_INDEXABLE=false` и `FORM_DELIVERY_ENABLED=false`. База D1 и хранилище R2 проекту не требуются.
5. После загрузки проверить главную, каталог, ABS, форму, `/privacy`, `/robots.txt`, `/sitemap.xml`, отсутствующий адрес и `/editor/index.html` (должен возвращать 404).
6. Только после проверки предварительного адреса и решения владельца переносить домен. При переносе изменить `SITE_ORIGIN`, утвердить документы и маршрут обработки данных, пересобрать, затем включить индексацию. Сохранить возможность отката к прежнему Worker.

`.github/workflows/check.yml` запускает lint, TypeScript, проверку каталога и сборку при push/PR. Этот workflow сам сайт не публикует. Уже существующая внешняя интеграция Cloudflare может публиковать изменения автоматически — учитывать при выборе репозитория/ветки.

`.openai/hosting.json` и плагин Sites оставлены от исходного проекта. В этой работе через Sites ничего не публиковалось. Cloudflare проверяется по фактическому артефакту `dist/server/wrangler.json`.

## Обработка персональных данных перед публичным запуском

Созданы отдельные `/privacy` и `/consent`, ссылка на оба документа возле непредустановленного чекбокса, версия согласия. В автоматическом режиме версия и дата отправляются вместе с заявкой. Форма не сохраняет введённые поля в localStorage; пустой upload-контрол, который не передавал файлы, заменён явной отправкой чертежа по почте.

Необходимо назвать оператора и адрес, подтвердить получателя `info@exapolymer.ru`, утвердить сроки/процедуру удаления писем и порядок доступа. По сохранённым заметкам старого проекта почта использовала Cloudflare Email Routing → Gmail; актуальная настройка аккаунта в этой работе не проверялась.

Web3Forms сообщает о серверах в США: https://docs.web3forms.com/getting-started/faq . Наличие политики и чекбокса само по себе не решает вопросы локализации, поручения обработки, уведомлений и трансграничной передачи. Перед включением автоматического приёма заявок необходимо проверить фактический маршрут обработки; для аудитории РФ рассмотреть обработчик/почту с необходимым размещением данных и подтвердить применимые требования. Справочный первоисточник: Федеральный закон №152-ФЗ — https://www.kremlin.ru/acts/bank/24154/print .

Режим подготовки письма не является заявлением о юридическом соответствии: после отправки письма обработку всё равно выполняет оператор и его почтовые провайдеры. Документы остаются проектами до утверждения владельцем. Банковские и платёжные реквизиты по решению владельца не добавлены.
